# วิธีทำงานร่วมกับผู้ใช้

ที่มา: คำสั่งโดยตรงระหว่างงาน Sweet Talk วันที่ 16 ตุลาคม 2026 ใช้เป็นแนวทางร่วมกัน ไม่แทนคำสั่งล่าสุด

## ก่อนแก้

- ผู้ใช้ต้องการเห็นแผนคร่าว ๆ และตอบตกลงก่อนแก้ทุกครั้ง
- แผนต้องบอกว่าจะเปลี่ยนอะไร ตรงเวลาไหน เวอร์ชันใด และส่วนใดได้รับผลกระทบ
- ถ้าเป็นทรานซิชัน ให้แจกแจงรายจุด ไม่ใช้คำกว้าง ๆ ว่าจะทำให้สวยขึ้น
- ถ้ามุมกล้องใหม่กระทบฉากหลัก ให้ออกแบบท้ายฉากเดิมและต้นฉากถัดไปด้วย รวมตัวละคร เนื้อเพลง และพร็อพ
- เมื่ออนุมัติแล้ว ดำเนินงานในขอบเขตนั้นได้ ไม่ถามยืนยันซ้ำโดยไม่มีเหตุใหม่

## รักษาขอบเขต

- แก้เฉพาะจุดที่ระบุ อย่าขยายคำขอเฉพาะทรานซิชัน 1:36 และแสง ไปเป็นการเปลี่ยนทรานซิชันทั้งหมด
- เมื่อสั่งแก้เฉพาะ B ต้องรักษา A และตัวเดิมไว้
- เก็บเวอร์ชันก่อนเปลี่ยนทิศทาง และใช้ A/B เมื่อผู้ใช้ขอทดลองเปรียบเทียบ
- สิ่งที่ผู้ใช้ตอบให้ลองทำยังไม่เท่ากับยืนยันว่าชอบผลสุดท้าย

## โควต้าและงานที่ยืดเยื้อ — ข้อกำหนดสำคัญ

ผู้ใช้ชี้แจงว่าไม่ได้ต้องการแค่ให้รายงานน้อยลง: **ถ้าทำไปสักพักแล้วมีโอกาสใช้โควต้าเยอะ ให้ถามก่อนทำต่อ และเสนอวิธีแก้ปัญหา**

เมื่อถึงจุดนั้นให้แจ้งสั้น ๆ:

1. ทำอะไรเสร็จแล้ว และเหลืออะไร
2. สาเหตุที่งานเริ่มแพง/ช้า เช่น เรนเดอร์เต็มเพลง ภาพใหญ่ หลายเลเยอร์ หรือการตรวจซ้ำ
3. สิ่งที่ทราบจริงเกี่ยวกับเวลาและค่าใช้จ่าย ถ้าไม่ทราบจำนวนโควต้าให้บอกว่าไม่ทราบ ห้ามแต่งตัวเลข
4. ทางเลือกพร้อมข้อแลกเปลี่ยน แล้วรอคำตอบก่อนทำส่วนที่แพงต่อ

ตัวเลือกที่เหมาะกับงานวิดีโอ:

- เรนเดอร์เฉพาะช่วงที่แก้ เช่น 5–15 วินาทีหรือภาพตัวอย่างไม่กี่เฟรมก่อน
- ทำ MP4 ความละเอียดต่ำสำหรับตรวจจังหวะ แล้วค่อยส่งออกตัวจริงเมื่อเลือกแบบแล้ว
- ใช้สำเนาภาพขนาดเล็กสำหรับพรีวิว โดยเก็บต้นฉบับและจังหวะเสียงไว้
- ปล่อยงานเรนเดอร์ในเครื่องและกลับมาตรวจเมื่อจำเป็น แทนการเรียกเครื่องมือ/รายงานเปอร์เซ็นต์ถี่ ๆ
- ให้ผู้ใช้เลือกทำต่อ หยุด หรือกลับมาตรวจภายหลัง โดยไม่รับปากว่าจะมีการแจ้งอัตโนมัติถ้าไม่ได้ตั้งระบบไว้

บทเรียนจากงานนี้: การวนเช็กสถานะและเล่าเปอร์เซ็นต์ทุกช่วงระหว่างเรนเดอร์เต็มเพลงใช้การโต้ตอบมาก ผู้ใช้ขอให้มีจุดตัดสินใจก่อนงานใช้โควต้าสูง ไม่ใช่ให้ทำยาวต่อไปแล้วเพียงเงียบลง

## ส่งมอบและส่งต่องาน

- แยกสถานะ: ทำใน Studio แล้ว / ตรวจภาพตัวอย่างแล้ว / เรนเดอร์ไฟล์แล้ว / ตรวจ metadata และถอดรหัสแล้ว / ผู้ใช้ยืนยันแล้ว
- เก็บลิงก์ composition และชื่อไฟล์ให้ชัดเจน อย่าส่งเวอร์ชันเก่าแทนงานล่าสุด
- ระบุข้อจำกัดจริง เช่น จังหวะคำย่อยที่ประมาณจากกลุ่มคำ หรือแขนกับเค้กที่ยังเป็นเลเยอร์เดียว
- ถ้าเครื่องมือถูกบล็อกหรือคำสั่งไม่สำเร็จ ให้บอกตามจริง ไม่รายงานว่าตรวจ UI แล้ว
- จบเซสชันด้วยสิ่งที่ต้องทำต่อและสิ่งที่ไม่ควรถามผู้ใช้ซ้ำ
